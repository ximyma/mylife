**基线 v0.4.1** ｜ 2026-10-24 ｜ 定位：**继续单机运行**（Windows EXE / Android APK / 浏览器），不做云端、不做多端同步
前置文档：`docs/MILESTONE-3-PLAN.md`（长期平台化路线，与本方案并行不冲突）

## 一、五条设计原则（先定下来，后面所有取舍都靠它）

1. **原文不可变**。老人说的原话是档案的本体，AI 润色、改写、剧本化一律进「版本表」，界面永远能退回原文。这条不做，第 3 项就是个销毁档案的功能。
2. **离线优先**。编辑、排版、导出、朗读、配乐混音必须断网可用；只有「模型生成」类动作需要联网。联网时明确告示，断网时给可用替代（如系统 TTS 代替云端 TTS）。
3. **成本可见**。所有 AI 动作执行前显示「预计消耗」（几张图 / 多少字 / 多少秒），执行后记账。单机版用的是用户自己的 Key，悄悄烧钱是设计事故。
4. **素材可重建**。缩略图、转码、裁切、合成结果全部放 `files/derived/` 与 `files/ai/`，只记参数，不当作原始数据；删掉能按参数重算。
5. **桌面优先，手机降级**。视频合成、大文档导出只在桌面做；手机端做采集、编辑、预览。这不是偷懒，是 Android 上没有 ffmpeg 而 WebView 又扛不住渲染的现实。

## 二、P0 共同基座（1.5 周，必须先做）

### 2.1 资源目录规范

```
data/users/<uid>/files/
  originals/      原图、原录音（用户上传或录制的，永不修改）
  derived/        缩略图 / 转码 / 裁切（可删可重建）
  ai/img|tts|music|video/   模型产物
  exports/        docx / pptx / pdf / mp4 / zip
```

新增表 `derivations(id, source_path, params_hash, out_path, created_at)`：同一源文件 + 同一参数只算一次，命中即复用。**这条让「生成 100 张缩略图」不重复付费、不重复耗时。**

### 2.2 任务队列（所有耗时操作的统一出口）

现在所有请求都是同步的（`apiAi` 直接 await）。图片生成、视频合成、100 章 PDF 动辄几十秒到几分钟，同步做会把界面卡死、手机端还会被系统杀掉。

```sql
CREATE TABLE jobs (
  id INTEGER PRIMARY KEY, uid INTEGER, type TEXT,          -- image/tts/music/video/export/polish
  payload_json TEXT, status TEXT,                           -- queued/running/done/failed/canceled
  progress REAL DEFAULT 0, stage TEXT, error TEXT,
  created_at TEXT, started_at TEXT, finished_at TEXT, cancel_flag INTEGER DEFAULT 0
);
```

- worker 单线程，300ms 轮询取一条 `queued`，逐条执行；
- 前端 1 秒轮询 `GET /api/jobs/:id`，显示进度条与阶段文字（「正在渲染第 12/40 镜」）；
- 支持取消、失败重试、进程重启后把 `running` 复位成 `queued` 续跑；
- **不用 SSE**：安卓老 WebView 的 `EventSource` 带不了 Authorization 头，轮询在本地回环上开销可以忽略。

### 2.3 AI 能力网关

现有 `apiAi()` 只服务对话。扩成按能力路由，一处管 Key、超时、重试、降级、计费：

| 能力 | 接口 | 典型供应商 | 单机版默认 |
| --- | --- | --- | --- |
| `text` | `/chat/completions` | 硅基流动 / DeepSeek / 任意 OpenAI 兼容 | 已在用 |
| `asr` | `/audio/transcriptions` | 硅基流动 SenseVoiceSmall | 已在用 |
| `image` | `/images/generations` | 硅基流动 Kolors 类 | 待接入 |
| `tts` | `/audio/speech` | CosyVoice 类 / 系统 TTS 兜底 | 待接入 |
| `music` | 音乐生成接口 | 供应商待探测 | 可选 |
| `video` | 视频生成接口 | 按秒计费，默认关闭 | 可选 |

每条能力带**有序降级链**（如 `image: 供应商A → 供应商B → 报错并给出配置指引`），调用结果写 `ai_usage(id, capability, model, units, unit, cost_estimate, at, ref)`。

### 2.4 统一文档模型

导出三件套（docx/pdf/pptx）如果各写一套排版逻辑，改一处要改三处。做法：先把档案转成一份与格式无关的中间模型，再让三个渲染器各自消费。

```js
// server/export/model.js 输出
{
  meta: { title, subject, years, archiveNo, portrait },
  cover: { style, title, subtitle, portraitPath, year },
  toc: [ { level, title, page } ],
  chapters: [ {
    seq, title, years, quote,
    blocks: [ { type:'text', text, isQuote },
              { type:'photo', path, caption, year },
              { type:'audio', path, caption, duration },
              { type:'script', scene } ]
  } ],
  appendix: { facts, timeline }
}
```

`HTML 印刷版`、`docx`、`pptx` 都从这里读，**页码/分页由各自渲染器决定**（印刷版靠 CSS，docx 靠分页符，pptx 靠分页）。

### 2.5 构建期依赖策略

项目现在是「运行时零依赖」（安卓端零第三方库）。新功能需要一些纯 JS 库：

| 库 | 用途 | 体积 | 处理 |
| --- | --- | --- | --- |
| `docx` | 生成真 .docx | ~1 MB | 构建期打包进 SEA，运行时仍是单文件 |
| `pptxgenjs` | 生成 .pptx | ~2 MB | 同上 |
| `ffmpeg` 静态二进制 | 视频/音频合成 | ~35 MB（精简滤镜） | 随 EXE 分发，首次运行解压到 `tmp/bin` |

**原则不变：用户侧仍然双击即用，不需要装 Node、不需要 npm install。** 依赖只是从「运行时」挪到了「构建时」。

## 三、逐项方案

### P1 · 封面与头像（1 周）

**现状**：只有 `archives.cover_photo_id` 指向一张照片，没有「头像」概念，也没有版式；删除照片时不检查是否正被用作封面。

**概念先拆清楚**，这是这个功能的全部：

| 概念 | 含义 | 出现位置 |
| --- | --- | --- |
| **头像 portrait** | 人物肖像，方图裁成圆 | 首页卡片右下角、封面角标、导出扉页、分享卡 |
| **封面 cover** | 一本书的封面构图 | 首页大卡、导出封面页、分享页头图 |

两者可以是同一张照片，但必须分别存储——换封面不该顺手换掉头像。

**数据**：

```sql
ALTER TABLE archives ADD COLUMN portrait_photo_id INTEGER;   -- 头像
ALTER TABLE archives ADD COLUMN cover_config_json TEXT;      -- {style, titleFont, accent, crop, showYear}
ALTER TABLE photos   ADD COLUMN role TEXT DEFAULT 'inline';  -- inline/portrait/cover
ALTER TABLE photos   ADD COLUMN crop_json TEXT;              -- {x,y,w,h,rotate}
```

**交互**：档案页封面区点击 → 「封面工坊」抽屉

- 左：3:4 实时预览（真渲染，不是缩略示意）
- 右：选图（从照片库 / 上传 / 拍照 / AI 生成）、九宫格裁切、4 套版式、3 种标题字体、6 个主色
- 版式全部用 CSS + SVG 实现（素纸 / 暗角 / 双色烫金 / 胶片），**不引入任何图片素材**，所以不增加体积
- 头像单独一栏：选图 → 圆形裁切 → 三档预生成（400 / 160 / 96 px）存 `derived/`

**引用保护**：删照片前查 `cover_photo_id` / `portrait_photo_id`，被引用则提示「这张正在当封面，先换一张」而不是直接删。

**验收**：增删改查全通；裁切参数重启后仍在；换封面不动头像；导出 PDF 的扉页用的是头像；320px 宽无横向滚动。

### P2 · 任意时间点插入内容（1.5 周）

**现状**：只有 `chapters.seq` 与 `entries.seq`，顺序是「章内第几条」，没有时间坐标。`segments` 只有一个 `year_hint`。

**做法**：给四类内容加统一时间字段，再用视图合成时间轴，不做多态表（多态表在这个体量是负债）。

```sql
-- entries / segments / photos / media 各加：
at_year INTEGER, at_month INTEGER, at_day INTEGER,
at_precision TEXT,   -- year/quarter/month/day/unknown
at_label TEXT        -- 「一九六二年开春」这种说不清的日子，原话照录
```

```sql
CREATE VIEW v_timeline AS
  SELECT 'entry' AS kind, id, archive_id, at_year, at_month, at_day, at_precision, at_label, chapter_id FROM entries
  UNION ALL SELECT 'segment', ... UNION ALL SELECT 'photo', ... UNION ALL SELECT 'media', ...;
```

**排序稳定性**：`entries.sort_key REAL`，拖拽时取相邻两条的中值；中值撞车（浮点精度耗尽）就整章重排为 10/20/30。**永不靠 `seq` 加减 1**——那是最容易写出重复序号的写法。

**三个入口**（缺一个用户就会骂）：

1. 时间轴视图的年份刻度上点「+」→ 选类型（文字 / 图片 / 音频 / 视频）→ 填年份 → 写内容；
2. 任意条目行尾「在此后插入」→ 继承该条目的年份；
3. 照片 / 录音直接拖到时间轴的某个年份上 → 自动落位。

**未定年份**的内容进「待定区」，不强行归章。生成卷宗时，`at_year` 落在某章范围内的自动归章，但允许手动改。

**验收**：在 1962 年 3 月插入一段音频，时间轴、章节视图、导出文档三处位置一致；连续拖拽 20 次无序号冲突；插叙后重新生成卷宗不丢内容。

### P3 · 导出可打印 / 可展示的文档（2.5 周）

**现状**：只有 `.mylife.json` 整档备份（把照片、录音 base64 塞进一个 JSON），没有任何排版导出。

四条产线，共用 P0 的文档模型：

| 产物 | 路径 | 质量 | 依赖 |
| --- | --- | --- | --- |
| **印刷版 HTML** | `/export/book/:id?size=a5&theme=paper` | 高（CSS 精排） | 无 |
| **PDF** | 打印 HTML / 桌面端 headless Chrome | 高 | Chrome/Edge 或系统打印 |
| **DOCX** | `docx` 库直接生成 | 中高（可在 Word 里改） | 构建期依赖 |
| **PPTX** | `pptxgenjs`，16:9 | 高（放映用） | 构建期依赖 |

**印刷版 HTML 的关键细节**（这些不做，打印出来就是一团糟）：

- `@page { size: A5; margin: 18mm 16mm; }`，正文 10.5pt / 行高 1.75；
- 每章 `break-before: page`，图片 `break-inside: avoid`，避免图被切两半；
- 目录页码用 CSS `target-counter(attr(href), page)`（Chrome 支持）；
- 页眉放书名、页脚放页码，靠 `@page` 边距盒；
- 字体只用系统栈（`"Songti SC","SimSun","Noto Serif CJK SC",serif`），**不嵌字体**——版权与体积都不划算，排版差异靠留白吸收。

**PDF 三种走法（按平台选，别指望一套通吃）**：

| 平台 | 做法 | 说明 |
| --- | --- | --- |
| Windows / macOS | 检测 Chrome/Edge → `--headless=new --print-to-pdf --no-pdf-header-footer` | 保真最高，一条命令 |
| 任意浏览器 | `window.print()` + 提示「目标：另存为 PDF」 | 兜底，永远可用 |
| Android | 生成 HTML 到 `exports/` → 系统浏览器打开 → 用户点打印 / 存为 PDF | **诚实说明：依赖系统打印服务，不是 100% 可控** |

**DOCX**：标题 1/2/3 用内置样式（这样用户能在 Word 里一键生成目录）、正文首行缩进 2 字符、图注居中小五、章节分页符、页眉书名、页脚页码、图片按版心宽度等比缩放。

**PPTX** 是「展示」而不是「搬运」，所以按视觉版式设计，六种页型：

封面页 → 时间轴页（一条线串起五个年代）→ 章节扉页（大字号引文）→ 图文对页（左图右文）→ 照片墙（4/6/9 宫格）→ 结语页（一句原话 + 头像）

一页一章，条目超过 6 条自动拆页；照片墙按可用照片数自动选宫格数。

**导出记录**：`exports(id, uid, archive_id, kind, path, params_json, size, created_at)`，历史可重新下载，不必重复生成。

**验收**：100 章 / 300 张照片的档案，PDF 生成 < 60 秒、无图片溢出、目录页码正确；docx 在 Word 2019 与 WPS 打开无「修复」提示；pptx 20 页可在 PowerPoint 直接放映。

### P4 · AI 助手（2 周）

**现状**：有 AI 配置中心、有生成卷宗、有转写。**没有对话**，也没有会话存储。

**五个角色**（本质是五套 system prompt，用户可改）：

| 角色 | 干什么 | 典型问法 |
| --- | --- | --- |
| 采访者 | 追问细节，一次只问一个问题 | 「1962 年换车间那天，你穿的是什么？」 |
| 编辑 | 润色、改错、统一称谓 | 「把这段整理成书面语，保留口语味道」 |
| 编剧 | 把章节改成分场剧本 | 「把第三章改成 5 场戏」 |
| 音乐人 | 写歌词（主题曲 / 场景歌） | 「写一首关于进厂那年的歌」 |
| 史官 | 对照年代背景，提示可补充的细节 | 「1956 年济南国棉三厂在招工吗？」 |

**上下文策略（不引入向量库）**：

```
system prompt（角色 + 档案人物卡 facts）
+ SQLite FTS5 命中的 top 8 条目（按关键词召回，中文按二元组切）
+ 最近 3 轮对话
+ 用户本次输入
```

预算控制 4000 字以内。这个体量的档案（几百条）用 FTS5 足够，向量库要多装一个 embedding 服务、还得多付一份钱，**不值得**。

**流式输出**：用 XHR 的 `onprogress` 增量读取，不用 `EventSource`（带不了鉴权头），也不用 `ReadableStream`（安卓 5/6 的 WebView 没有）。逐字上屏，用户能感到「在思考」。

**语音输入**：复用现有录音 + ASR 链路——录完自动转文字填入输入框，可编辑后再发。

**关键闭环（这是它区别于普通聊天的地方）**：每条回复下方有「插入档案」按钮 → 选章节 / 年份 → 生成一条 `entry`（状态 draft）→ 用户确认后落到时间轴。**聊天不能只产生聊天记录，要能变成档案。**

**隐私面板**：发送前显示「本次将上传：档案摘要 480 字 + 3 条相关记录 620 字」，可切换「只发我选中的片段」。档案是私密内容，默认必须让人看得见发了什么。

**验收**：断网给出明确提示不吞消息；20 轮长会话不崩；引用到的条目在回复里可点开原文；插入档案后时间轴位置正确。

### P5 · AI 语音与音乐（2.5 周）

这是六项里最讨喜、也最容易翻车的一项。拆成三层，每层都有离线兜底。

#### 5.1 朗读音色（TTS）

| 档 | 实现 | 成本 | 离线 | 音质 |
| --- | --- | --- | --- | --- |
| 系统 TTS | 安卓 `TextToSpeech` / 浏览器 `speechSynthesis` | 0 | 是 | 一般（现有能力） |
| 云端 TTS | 供应商 `/audio/speech`，生成 mp3 落盘 | 按字计费 | 否 | 好 |
| 克隆音色 | 上传样本克隆 | 高 | 否 | 好但有伦理风险 |

- **缓存是刚需**：`ai_assets` 按 `hash(text + voice + speed)` 命中即复用，同一段文字读十次只付一次钱；
- 长文按句切分、逐句合成再拼接（避免单次长度上限），断点续传；
- 克隆音色默认关闭，开启时要求勾选「我确认这是本人声音且已获授权」——已故亲人的声音克隆，伦理上必须有这道闸。

#### 5.2 配乐与实时混音

**内置免版税 BGM 库**（`assets/bgm/`，6 首：怀旧钢琴 / 口琴 / 民谣吉他 / 弦乐 / 老唱片 / 轻快，各 60–90 秒可循环，总 < 8MB）。选择逻辑按章节情绪词匹配（「离别 / 团聚 / 辛苦 / 欢喜」）。这部分的成本是 **0**，且 100% 离线可用。

混音不用 ffmpeg，用 **Web Audio**：

```
朗读音频 → GainNode(1.0) ┐
                          ├→ DynamicsCompressor → 输出
BGM 循环 → GainNode(0.18)┘   （朗读时把 BGM 压到 0.18，句间空隙抬到 0.35）
```

好处：拖动滑块实时听效果、零额外依赖、安卓 WebView 也支持（注意必须在用户点击回调里创建 `AudioContext`，否则被自动播放策略拦掉）。

需要导出成片时（放给不会用手机的亲戚听），再走 ffmpeg `amix` + 音量包络。

#### 5.3 主题曲与场景歌

```
档案 → 歌词生成（LLM，注入年代/地名/口头禅/关键事件）
     → 音乐生成接口（若可用）
     → mp3 存 ai/music/
     → 可设为「档案主题曲」，用于朗读开头、短片片尾
```

诚实的边界：**国内音乐生成 API 的可用性不稳**（多数要海外支付或审核），所以给三级降级：

1. 音乐生成接口可用 → 真·歌曲（有旋律有唱）；
2. 接口不可用 → **「歌词 + 朗诵 + BGM」的诗朗诵版本**（LLM 出词，TTS 念白，BGM 铺底，本地合成，成本 0）；
3. 连 TTS 都没有 → 歌词文本 + 朗读，可导出 LRC。

用户拿到的是「能听的东西」，而不是一句「接口不可用」。

**歌词生成的质量要点**（写进 prompt 模板）：三段式（主歌 1 / 副歌 / 主歌 2 / 副歌 / 尾声）、每句 7–11 字、必须含至少两个档案里的真实地名或物件、禁用空泛的「岁月如歌」类套话。

**验收**：同一段文字重复朗读只调一次接口；朗读时 BGM 自动避让、可关；主题曲能设为档案背景并在短片中引用；断网时自动回落到系统 TTS 并提示。

### P6 · 润色 / 剧本 / 插图 / 漫画（3 周）

#### 6.1 润色（先做，性价比最高）

```sql
CREATE TABLE entry_versions (
  id INTEGER PRIMARY KEY, entry_id INTEGER, kind TEXT,      -- polish/rewrite/script
  style TEXT, text TEXT, status TEXT,                        -- proposal/accepted/rejected
  model TEXT, cost REAL, created_at TEXT
);
```

**三条铁律**：原文只读；AI 结果只进 `entry_versions`；采纳必须人点一次。

界面：左右并排 + 词级 diff 高亮（纯 JS 的 LCS 实现，约 80 行），可「整段采纳 / 逐句采纳 / 全部丢弃」。风格预设 5 种（保留口语 / 书面化 / 文学化 / 方言优先 / 精简）。批量按章时先显示「预计 12 次请求，约 2.4 万 tokens」。

#### 6.2 剧本

`scripts(id, archive_id, chapter_id, json, created_at)`，JSON 结构：

```json
{ "scenes": [ { "no": 1, "slug": "内景 · 车间 · 日",
  "time": "1956 年春", "place": "国棉三厂细纱车间",
  "chars": ["桂芳", "孙师傅"],
  "action": "上百台织布机同时轰鸣，桂芳站在门口不敢进。",
  "dialogue": [ {"who":"孙师傅","line":"先看我接线头，看三天。"} ],
  "voiceover": "那年我十六岁。" } ] }
```

提示词硬约束：**只允许使用档案中出现的事实，不得虚构人名与事件**；不确定的细节标 `[待考]` 让用户补。导出走 P3 的文档模型（剧本格式：场次号 + 场景头 + 动作 + 对白缩进）。

#### 6.3 插图

能力 `image`，八种风格预设（年代照片 / 水彩 / 连环画 / 水墨 / 油画 / 剪纸 / 版画 / 像素）。两个提升可用性的技巧：

- **年代一致性**：提示词模板自动注入年代、地点、服饰特征（「1960 年代山东济南，蓝布褂子，棉纺厂车间」），否则模型默认画成现代人；
- **形象一致性**：给同一人物生成「人物设定卡」（年龄、发型、衣着、面部特征），后续每张图都带上这段描述 + 固定 seed。做不到 100% 一致，但能避免「每张图换个人」。

生成结果一律标 `ai_generated=1`，导出时在图片下方小字标注「AI 生成插图」——这是《人工智能生成合成内容标识办法》的要求，也是对自己的保护。

#### 6.4 漫画书

`storyboards(id, archive_id, chapter_id, layout, json)`。四种版式：四格 / 六格 / 条漫 / 整页。渲染用 SVG 合成（图片 + 分格边框 + 对白气泡），中文气泡按字符宽度估算换行（**不能靠浏览器自动换行，导出成图时会溢出**）。产出 PDF 或 PNG 长图，可直接发家族群。

**验收**：润色后原文一字未动、可一键回退；剧本 5 场结构完整且无虚构人名；插图 10 张里人物形象至少能认出是同一人；漫画导出 20 页无气泡溢出。

### P7 · 短视频 / 电影合成（3 周）

管线六步，每步都是可预览、可单独重跑的：

```
剧本/章节 → 分镜(storyboard) → 配音(TTS) → 配乐(BGM) → 画面(插图+运镜) → 合成(ffmpeg)
```

**两种模式，成本差 100 倍，默认走便宜的那个**：

| 模式 | 画面来源 | 成本 | 3 分钟片渲染耗时 | 适用 |
| --- | --- | --- | --- | --- |
| **图文影**（默认） | 静态插图 + Ken Burns 运镜 + 字幕 + 配音 + BGM | ≈ 0（只花图片钱） | 2–4 分钟 | 90% 的场景 |
| **AI 动态**（可选） | 视频模型生成 3–5 个关键镜头 | 按秒计费，**每秒 0.5–2 元** | 取决于供应商排队 | 片头 / 高潮 |

界面必须先显示「本片预计消耗：12 张图 + 3 个视频镜头 ≈ 18 元」，用户点确认才跑。这条不做，用户会被账单吓到。

**ffmpeg 关键滤镜**（都是踩过坑的）：

- `zoompan` 做缓慢推拉（`z='min(zoom+0.0008,1.12)'`），**必须显式指定输出帧率与尺寸**，否则会掉帧或变形；
- 字幕走 ASS（本项目已有硬字幕经验：毫秒要转百分秒、行内边距要显式写、长 CJK 行要手动 `\N` 换行）；
- 音频 `amix` + `sidechaincompress` 做 ducking（朗读时自动压低 BGM），比固定音量自然；
- 输出 `-c:v libx264 -preset veryfast -crf 23 -pix_fmt yuv420p -c:a aac -b:a 128k`，`yuv420p` 不加的话某些播放器黑屏。

**两种画幅**：竖屏 1080×1920（发视频号 / 抖音）、横屏 1920×1080（家族聚会投影）。

**安卓端只做**：分镜编辑、预览关键帧、上传素材；渲染交给桌面端。这条写进界面提示，不要让用户等半小时后失败。

**验收**：3 分钟竖屏短片在桌面渲染成功、音画同步（误差 < 100ms）、字幕不溢出、在微信里能正常播放；同一工程可换横屏重出。

## 十、验收（DoD）

1. 六项功能在 Windows 与 Android 两端逐项通过，能力矩阵里标「否」的项在界面上明确禁用而不是静默失败；
2. 任何 AI 加工后，原文可通过一次点击完整还原（自动化测试覆盖）；
3. 100 章 / 300 图 / 50 段录音的真实档案：封面设置 < 100ms、时间轴滚动 60fps、PDF < 60s、DOCX < 30s、PPTX < 30s；
4. 断网状态下：编辑、插叙、封面、导出 HTML、系统 TTS 朗读、BGM 混音全部可用；
5. 所有 AI 动作执行前有成本提示，执行后 `ai_usage` 有记录，可在设置页看到本月花费；
6. 新增自动化测试 ≥ 80 项（封面/时间轴/导出/版本/任务/降级），连同现有 197 项全绿。

## 十一、明确不做

- 云同步、多人协作、账号体系升级（属于平台化路线，单机版不碰）
- 真实视频生成替代分镜（成本不可控，只做小片段点缀）
- 声音克隆的批量音色库（伦理与合规风险大于收益）
- 矢量插画编辑器（用现成图片 + 版式模板即可）
- 音乐生成的本地模型（体积与算力都不现实，走 API + 降级）
