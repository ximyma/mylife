## 二、分阶段技术路线图

### Phase 0：零成本养用户期（现在 → 日活 1,000）

**目标：不加任何服务器。所有开发只做本地功能与传播工具。**

| 任务 | 技术要点 | 商业意义 |
|---|---|---|
| 导出长图（小程序） | canvas 按章节渲染 → wx.saveImageToPhotosAlbum | 老人最友好的"拿到成果"方式；导出入口预留额度闸 |
| 分享卡片 | onShareAppMessage 自定义图（档案封面+章节摘句） | 家庭群裂变主通道 |
| 分享解锁 +1（额度系统本地版） | store.js 加 quota 模块；计数存 wx.storage（清数据=删档案，天然防刷） | 为阶段一广告解锁预留同一接口 |
| 数据迁移助手 | 网页版 JSON ↔ 小程序 JSON 导入导出（schema 统一） | 三端数据同源承诺，建立信任 |
| 备份格式规范化 | 制定 backup-schema v1（版本号+档案+条目+照片 base64 可选包） | 未来云备份、成书、B 端全部吃这一个格式 |

**退出条件**：日活 > 1,000 持续 2 周 → 启动 Phase 1。

### Phase 1：商业化基建期（日活 > 1,000）

**目标：把"收钱的三条路"（订阅/成书/广告）的管线全部铺好。开发预算约 3–4 周。**

| 模块 | 技术方案 | 月成本估算 |
|---|---|---|
| 统一后端 | 轻量云服务器（2C2G）+ Node.js/Express，复用 server.js 现有代码 | 30–60 元 |
| 账号体系 | 小程序 wx.login → openid；公众号/网页用 UnionID 打通（微信开放平台绑定）；手机号兜底 | 0 |
| 云备份 | 对象存储 COS（0.1 元/GB/月）+ 端侧 AES 加密后上传；增量备份（只传 diff） | 1 万用户约 30–100 元 |
| 额度系统服务端化 | 按 UnionID 记账，本地额度无缝迁移（首次登录导入） | — |
| 微信支付 | 个体户主体；订阅（云备份）+ 单笔（成书） | 0.6% 手续费 |
| 激励视频广告 | 流量主（UV≥500 已过）→ 广告解锁额度 | 收入项 |
| 监控告警 | 云函数日志 + 免费额度内 uptime 监控 | 0 |

### Phase 2：商业化深化期（付费验证通过后）

按"付费意愿 × 开发成本"排序，逐个上线：

| 新功能 | 技术要点 | 收费设计 | 可行性 |
|---|---|---|---|
| **回忆录成书** ⭐ | 服务端排版引擎（HTML→印刷 PDF，复用现有分章结构）；对接按需印刷 API | 100–300 元/本，利润率 50%+ | ★★★★★ 核心付费点 |
| **家族协作共编** | 档案共享（家庭成员扫码加入）；角色权限（主笔/贡献者/阅览）； contributions 流 | 家族版 30 元/年 | ★★★★ 天然裂变 |
| **AI 深度访谈模式** | 多轮追问式引导（按年代/主题模板提问）；AI 总结成节 | 订阅增值 | ★★★★ 提升内容质量=提升成书转化 |
| **传记朗读/语音纪念** | TTS 全册朗读；长辈原声片段混入（已有录音资产） | 订阅增值 | ★★★ 情感浓度高 |
| **数字纪念页** | 逝者档案转纪念空间（家属共护、忌日提醒、可分享） | 单册 50–100 元 | ★★★ 延伸生命周期，需谨慎合规 |
| **AI 作曲（全家福之歌）** | 已有桌面版 AI 作曲链路，移植到服务端任务队列 | 单次 5–10 元 | ★★★ 差异化亮点 |
| **场景模板体系** | 分章+排版引擎复用，仅新增模板与引导词：宝宝成长册/金婚纪念册/恋爱时光机/周年纪念等 | 生命周期纪念品按次收费 | ★★★★ 低成本扩张，覆盖全人生节点 |
| **人生短片** | 老照片 AI 修复 + 动态化（深度合成）+ 旁白配音 → 3–5 分钟"人生电影"，显著标注 AI 生成 | 单部 99–299 元 | ★★★★ 爆款传播钩子 |

### Phase 3：数字纪念馆与 B 端生态（企业主体就绪后）

旗舰业务：**数字纪念馆**——逝者档案自动转为家族纪念空间，是产品从"工具"变"事业"的关键跃迁，也是全生命周期商业闭环的终点（对标线下骨灰存放柜数万元费用的"数字化安葬"，二十年几千元）。

| 模块 | 技术要点 |
|---|---|
| 纪念空间引擎 | 档案只读化转制 + 两级访问权限（亲友私密 / 完全开放瞻仰）+ 缅怀交互（献花/点烛/留言，去迷信化设计以过平台审核） |
| 长周期存储承诺 | 数据全量多副本 + 定期完整性校验 + 用户侧随时导出自由 + 书面存续承诺书（化解"公司倒了数据怎么办"的成交障碍） |
| 人生短片流水线 | 修复/动态化/配音 GPU 任务队列，深度合成内容显著标识（合规硬要求） |
| B 端渠道系统 | 殡仪馆/公墓/白事服务商分销码 + 分成结算后台（介绍一单分 20–30%） |
| 机构 SaaS | 养老机构/社区"长者人生档案"批量账号 + 机构管理台 |

其他：开放 backup-schema 格式吸引第三方工具生态、出版社"家族史丛书"通道、电子相框硬件延伸（远期）。

**生命服务线合规实施前提（不满足则不上线）**：①企业主体 + 相应类目资质（个人主体不发殡葬类内容）；②缅怀交互去迷信化，规避小程序平台封建迷信审核红线；③AI 修复/动态化内容按《互联网深度合成管理规定》显著标识；④定价与传播叙事围绕数据维护成本，品牌姿态是守护者而非生意人。

## 四、前景评估（客观版）

### 4.1 技术前景

| 维度 | 评估 | 说明 |
|---|---|---|
| 架构可持续性 | ★★★★★ | 零边际成本架构在用户增长时成本曲线平缓，无"增长即亏损"风险 |
| 技术壁垒 | ★★★☆☆ | 单点技术不深，但三端同构+适老化打磨+成书交付链的组合有壁垒 |
| AI 演进受益 | ★★★★★ | 模型越强（长文本、语音克隆、多模态），本产品免费获得能力升级，无需改架构 |

### 4.2 商业前景

| 维度 | 评估 | 说明 |
|---|---|---|
| 需求真伪 | 真 | StoryWorth 验证付费、人工回忆录验证高价，空白带真实存在 |
| 天花板 | ★★★☆☆ | 垂直场景，难成超级 App；但"纪念/传承"生命周期极长——一个家族可以是 10 年客户，数字纪念馆更把价值延伸到身后 20 年（存量只增不减） |
| 竞争风险 | ★★☆☆☆ | 大厂覆盖概率低；真正的风险是同类小团队先跑出品牌 |
| 现金流模型 | ★★★★☆ | 阶段一零成本；阶段二订阅打底+成书脉冲，很难亏损 |
| 最大的不确定性 | — | **获客**：工具类小程序自然流量差，成败取决于内容营销与家庭裂变能否点着火 |

### 4.3 结论

**技术上有前景**（架构在 AI 时代是顺势的，模型升级=产品升级）；**商业上有清晰的生存路径**（零成本活到日活 1,000，再用订阅+成书两条腿走路），但爆发上限取决于传播运营而非技术。适合作为"小团队+轻投入+情感品牌"路线的长期项目经营，不适合按"烧钱换规模"的互联网打法做。
