## 一、先搞懂一件事：为什么「上传了新代码，网站还是旧界面」

静态托管平台（阶跃星辰、Cloudflare Pages、Vercel 等）对 `.js` / `.css` 的响应头通常是：

```
cache-control: public, max-age=31536000, immutable
```

意思是"**一年内不许再问我，就用缓存**"。而 `index.html` 是 `no-cache`，每次都会重新取。

问题就出在：`index.html` 里写的是裸文件名 `<script src="app.js">`——文件内容换了，**网址没换**，浏览器按约定继续用一年前那份缓存，连一个校验请求都不发。所以你看到的是旧界面，服务器上其实已经是新文件。

（2026-11-02 实际踩过：线上 9 个文件逐个比对字节数，全部与本机一致，确认部署成功，纯粹是浏览器缓存。）

### 解决办法：打包时给资源加版本戳

`tools/pack-static.py` 会自动把

```html
<script src="app.js"></script>
```

改成

```html
<script src="app.js?v=v0.9.42-202611021118"></script>
```

地址一变，旧缓存立刻失效，用户普通刷新就能看到新版，不用教他清缓存。28 处 js/css 引用全部自动处理，`index.html` 本身 no-cache 能带动这些新地址。

**所以：不要手工改 `mylife-static/index.html`，也不要把目录直接拖上去，一律用下面的脚本打包后再上传。**

## 二、打包（必须走这一步）

```bash
cd D:\works\mylife1
python tools/pack-static.py
```

输出：

```
版本戳：v0.9.42-202611021118
改写资源引用：28 处
打包 31 个文件，跳过 ['schema.sql', '_localserver.py', '启动静态站.bat', 'sql-wasm.wasm']
产物：D:\works\mylife1\dist\岁月记录助手-静态站-v0.9.42-202611021118.zip  (0.96 MB)
校验：根目录 index.html ✓，内部版本戳 28 处 ✓
```

脚本做的事：

1. 从 `app.js` 读 `APP_VERSION`，拼上当前时间戳作为版本戳（每次打包都不同）；
2. 重写 `index.html` 里的 js/css 引用（**只改 zip 里的副本，源文件不动**）；
3. 排除平台拒收的 `.wasm` / `.sql`（数据链路已内嵌：wasm → `vendor/sql-wasm-b64.js`，建表语句 → `schema.js`）；
4. 排除本机自用的 `启动静态站.bat`、`_localserver.py`、`tmp/`、`.git` 等；
5. 自检：根目录必须有 `index.html`、版本戳数量要对得上、包内不能残留 `.wasm` / `.sql`。

想用固定戳（比如对某次发布留档）：`python tools/pack-static.py --stamp 20261102a`

## 三、阶跃星辰（page.stepcloud.com）更新步骤

1. 跑上面的打包命令，拿到新的 zip；
2. 打开阶跃星辰控制台里这个站点，**重新上传**这个 zip（覆盖式部署，不是新建站点）；
3. 等构建状态变成完成；
4. 验证：开一个**无痕窗口**（或换手机）打开站点链接，看界面是不是新版——
   无痕窗口没有旧缓存，能立刻反映真实部署结果；
5. 确认无误后，自己常用浏览器**普通刷新**即可（因为版本戳变了，不需要清缓存）。

### 关键：验收要用无痕窗口，不要用你平时的浏览器

平时的浏览器可能是几个月前的缓存在作怪，会让你误判"没上传成功"，然后反复上传、反复查代码，白折腾。

### 判断「到底是不是新版」的三个硬指标

| 方法 | 怎么操作 | 期望结果 |
|---|---|---|
| 看线上文件字节数 | 浏览器控制台 `fetch('app.js').then(r=>r.arrayBuffer()).then(b=>console.log(b.byteLength))` | 与本机 `app.js` 字节数一致 |
| 看资源地址带没带版本戳 | 控制台输入 `document.querySelector('script').src` | 结尾有 `?v=v0.9.xx-时间戳` |
| 看版本号 | 站点「设置 → 关于」里的版本文字 | 与 `app.js` 里 `APP_VERSION` 一致 |

辅助手段（命令行，能绕过浏览器缓存）：

```bash
curl -s "https://你的站点/app.js" | grep -o "APP_VERSION = '[^']*'"
```

## 六、常见问题

**Q：上传后提示部署成功，但打开还是旧版？**
A：99% 是缓存。先开无痕窗口看；无痕里是新版就说明站点没问题，让自己浏览器刷一下即可。若这次打包没带版本戳（手工拖的目录），那所有人都得手动清缓存——下次一定用 `pack-static.py`。

**Q：平台报错「不支持 .wasm / .sql 文件」？**
A：用了 `pack-static.py` 就不会有这两种文件。手工打包时务必排除。

**Q：zip 里要有 index.html 在根目录吗？**
A：要。压缩时选的是文件夹**里面的内容**，不是外层文件夹，否则会变成 `/站点名/index.html`，平台找不到首页。

**Q：手机上打开一片空白？**
A：先看是不是老安卓 WebView（本项目刻意用 ES5 就是为了兼容）；再确认是不是从微信里打开被拦了 Service Worker——本项目 SW 只负责把 `/files/*` 伪装成本地文件，页面资源不依赖 SW，SW 不可用也能正常用。
