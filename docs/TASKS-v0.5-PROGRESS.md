**三条使用规则**：

1. 每周一只认领 3–5 个任务，周五必须回归（跑全量测试 + 真机一次）。
2. 任务完成后先更新本表状态，再进入下一个——**表比记性可靠**。
3. 每个阶段结束必须产出**可运行、可分发的版本**（exe/apk 至少一个），不允许「全部做完再打包」。

## 四、为什么是这个顺序（不是随便排的）

| 顺序决策 | 理由 |
| --- | --- |
| P0 最前 | 目录、队列、网关、文档模型四件事，六项功能都要用。先做省五套重复代码 |
| P1 早于 P2 | 封面是「看得见」的改动，先拿到成就感；且 P3 导出要复用它 |
| P2 早于 P4 | 对话的「插入档案」必须落到时间轴上；时间轴没好，插进去只能落章尾 |
| P3 早于 P6 | 润色/剧本/漫画都要导出成文档；导出模型先定，后面三种产物白拿 |
| P4 早于 P6 | 润色、剧本、歌词本质都是「带上下文的对话」，共用一套会话与上下文 |
| P5 早于 P7 | 短片没有配音就是幻灯片；TTS 与 BGM 是短片的原料 |
| P6 早于 P7 | 短片画面来自插图与漫画分格；插图没好，短片只能拿老照片凑 |
| P8 单列 | 收口不是「顺手」，是防止「功能都有了、包发不出去」 |
