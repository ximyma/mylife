# 测试与调试指南（岁月记录助手）

> 2026-10-30 建立。配合 `docs/错误记录.md` 使用：测出 bug → 修 → 按编号追加记录。

## 一、现在的测试能力（本轮搭好的通路）

| 通路 | 用途 | 关键命令/工具 |
|---|---|---|
| **adb forward + curl** | 绕过 UI 直接测本地服务 API（登录/入库/查询/生图） | `adb forward tcp:18080 tcp:<端口>` + `curl --noproxy '*'` |
| **WebView DevTools 协议** | 在真机页面里执行任意 JS、看 DOM、抓报错 | `adb forward tcp:9222 localabstract:webview_devtools_remote_<pid>`；`mystory/devtools_eval.js "<js>"` |
| **批量路由巡检** | 一键遍历全部页面，收集 JS 异常/白屏 | `mystory/walkthrough.js <档案id>`（17 个路由约 1 分钟） |
| **模拟点击** | 走真实用户路径（登录/弹窗/按钮） | `input tap/text/keyevent`；坐标用 uiautomator dump 或 DevTools 取 rect×2.75 |
| **logcat** | 原生层报错（崩溃/权限/桥调用） | `adb logcat -d`（即时 dump，不挂后台） |

## 二、本轮已测过的（结论：主链路可用）

- ✅ 17 个页面全部渲染正常，无白屏、无 JS 报错
- ✅ 登录/会话、素材箱、收进档案弹窗全流程（小米9 Chrome 83 + 荣耀50 双机型）
- ✅ 文生图 → 自动入库 → 缓存命中；录音转文字（SenseVoiceSmall）
- ✅ 桌面 EXE 冒烟测试、静态站 zip 合规校验

## 三、还没深测的（风险区，按优先级）

1. **数据导入/导出**：备份恢复、导出 docx/pdf——数据损坏风险最高
2. **AI 访谈 / 电影生成 / 长文整理**：多步异步任务，超时/中断恢复没测过
3. **多用户与权限**：用户管理、改密、找回（Android 端 Auth 是新写的）
4. **弱网/断网**：AI 调用超时、重试、余额不足的表现
5. **大批量数据**：几千张照片、几百章节时的列表性能
6. **后台切前台**：录音/转写中途切走再回来
7. **桌面端与手机端同一账号并发写**：最后写入覆盖问题

## 四、以后怎么测（建议节奏）

### 每轮改代码后（最低要求，5 分钟）
1. `node --check` 全量 JS（历史教训：括号没配平整页打不开）
2. 走一遍改动面的链路（改了哪个功能就点哪条链）
3. 升版本号 → 打包 → 真机装

### 每个新版本发前（30 分钟）
1. `walkthrough.js` 全页面巡检
2. 四条核心链路手动点一遍：AI助手开→录音→转写→进段落；画图→入库→弹窗选图→插段落；素材箱→收进档案/存相册；登录→换账号
3. 小米9 + 荣耀50 各跑一遍（两台 WebView 内核差 4 个大版本，专抓兼容性）

### 环境备忘（踩过的坑）
- adb forward / logcat 后台进程**不跨命令存活**：转发和请求必须放同一条命令
- 小米9 截图坐标：物理 1080×2340，DevTools rect 需 ×2.75（dpr 2.75）
- MIUI 安全设置开启时 screencap 间歇 0 字节 → 用 `uiautomator dump` 或 DevTools 替代
- curl 必须 `--noproxy '*'`；adb 命令加 `MSYS_NO_PATHCONV=1`
- 小米9 WebView = Chrome 83：CSS 别用 Chrome 84+ 的东西（inset/aspect-ratio 已有垫片，新代码注意）

## 五、自动化方向（以后想省事可以加）

- walkthrough.js 已是半自动化骨架，可以加「每页截图留档 + 两次版本对比」做视觉回归
- API 层可以写一套 curl 脚本集（登录/CRUD/生图），打完包自动跑一遍
- 真 UI 自动化（uiautomator2 / Appium）投入大，现阶段手动+脚本混合性价比最高
